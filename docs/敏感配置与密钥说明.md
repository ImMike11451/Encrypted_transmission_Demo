# 配置与密钥说明

[返回项目首页](../README.md)

## 生成配置

在仓库根目录执行：

```bash
bash scripts/setup-demo.sh
```

脚本复制配置模板并创建各角色的 `shm` 目录，保留已存在的配置文件。

| 角色 | 配置模板 | 运行配置 |
| --- | --- | --- |
| 服务端 | `ServerSeckey/ServerSeckey/server.example.json` | `runtime/server/server.json` |
| Client A | `ClientSecKey/ClientSecKey/clientA.example.json` | `runtime/client-a/clientA.json` |
| Client B | `ClientSecKey/ClientSecKey/clientB.example.json` | `runtime/client-b/clientB.json` |

## 服务端配置

- `Host`、`UserDB`、`PassDB`、`ConnectDB`：实际 MySQL 主机、账户、密码和数据库名。将密码占位值 `change_me` 替换为实际密码。
- `ServerID`：服务端标识，默认 `6789`，需与客户端配置一致。
- `Port`：业务监听端口，默认 `9898`。
- `ShmKey`：共享内存标识所用路径，默认 `./shm`，相对于服务端运行目录。
- `ShmMaxNode`：共享内存节点容量，默认 `100`。

## 客户端配置

- `ClientID`：客户端标识，A 为 `0001`，B 为 `0002`。
- `ServerID`：目标服务端标识，默认 `6789`。
- `ServerIP`、`Port`：目标业务服务端地址和端口，默认 `127.0.0.1:9898`。
- `ShmKey`：默认 `./shm`，相对于各自的运行目录。
- `ShmMaxNode`：共享内存节点容量，默认 `1`。

三个角色分别使用独立运行目录。跨机器部署时修改客户端的 `ServerIP`，并保持服务端标识和业务端口一致。

## 密钥与本机文件

密钥协商会在运行目录中生成 RSA 密钥文件，会话密钥用于后续文本加密。实际数据库密码、私钥、会话密钥以及运行日志应只保存在受控的本机环境中。

`runtime/`、本机配置和 `*.pem` 已纳入忽略规则。共享项目时使用 `*.example.json` 模板，不附带真实凭据或运行时密钥。
