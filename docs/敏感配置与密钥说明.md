# 敏感配置与密钥说明

本文档说明哪些文件可以公开提交，哪些文件只能保留在本机。目标是让项目可以安全用于 GitHub 展示和面试演示，同时不影响本地双客户端联调。

## 可以提交的文件

- `server.example.json`
- `clientA.example.json`
- `clientB.example.json`
- 源代码、协议文件、数据库初始化脚本和中文说明文档

示例配置只能使用本地演示地址、端口和密码占位值，不能包含真实数据库账号、密码或私钥内容。

## 不可提交的文件

- `ServerSeckey/ServerSeckey/server.json`
- `ClientSecKey/ClientSecKey/client.json`
- `ClientSecKey/ClientSecKey/clientA.json`
- `ClientSecKey/ClientSecKey/clientB.json`
- `*.pem`
- 服务端运行时生成的 `客户端ID_pub.pem`

这些文件已加入 `.gitignore`。忽略规则不会删除本机文件，只会阻止新文件被 Git 意外跟踪。

## 本地配置步骤

1. 从 `server.example.json` 复制出 `server.json`，填写本机 MySQL 账号、密码和共享内存配置。
2. 从 `clientA.example.json`、`clientB.example.json` 分别复制出客户端配置。
3. 启动服务端后，先让 Client B、再让 Client A 完成密钥协商。
4. 客户端会在运行目录生成 `pri.pem` 和 `pub.pem`；服务端会保存对应客户端的公钥文件。

详细启动方式见 `docs/demo-guide.md`。

## 密钥泄露后的处理

如果私钥、真实数据库密码或真实配置被提交到远程仓库，不能只删除工作区文件。应立即执行以下操作：

1. 修改数据库密码。
2. 删除泄露的本地私钥和公钥文件。
3. 重新执行密钥协商，生成新的会话密钥和 RSA 密钥对。
4. 从 Git 历史和远程分支中清理泄露文件，并通知已获取仓库副本的人员。

当前项目用于本地演示。生产环境还应使用环境变量或专用密钥管理服务保存数据库凭据和私钥。

## 本次本机轮换结果

已为客户端 `0001` 生成新的 RSA 2048 位密钥对，并使用新公钥更新服务端的 `0001_pub.pem` 缓存文件。已验证私钥可读，且客户端公钥与服务端缓存公钥的指纹一致。

当前客户端实现会在每次密钥协商开始时重新生成 `pub.pem` 和 `pri.pem`，因此磁盘中预先生成的密钥只用于立即废弃旧文件；一次成功的协商仍会产生新的 RSA 密钥对和会话密钥。

数据库密码轮换未执行：当前 `server.json` 中的数据库密码无法通过本机 MySQL 身份验证。必须先通过可用的数据库管理员账户或既有部署凭据恢复管理权限，再单独执行密码轮换；不能在未验证旧凭据的情况下直接覆盖配置。
