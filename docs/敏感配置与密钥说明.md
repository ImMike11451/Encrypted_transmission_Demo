# 敏感配置与密钥说明

## 发布目录约定

Linux/WSL2 演示使用下列运行目录，而不是历史源码目录中的本机配置：

| 角色 | 运行目录 | 本机配置 |
| --- | --- | --- |
| 服务端 | `runtime/server/` | `server.json` |
| Client A | `runtime/client-a/` | `clientA.json` |
| Client B | `runtime/client-b/` | `clientB.json` |

执行 `bash scripts/setup-demo.sh` 后，脚本只会为缺失项创建目录和配置模板；不会覆盖已有文件、复制历史真实配置、执行数据库迁移或修改密码。三份配置的 `ShmKey` 约定为相对各自运行目录的 `./shm`。

## 示例与本机配置

可公开的示例配置位于：

- `ServerSeckey/ServerSeckey/server.example.json`
- `ClientSecKey/ClientSecKey/clientA.example.json`
- `ClientSecKey/ClientSecKey/clientB.example.json`

示例中的数据库密码必须保持占位值；本机 `server.json` 才填写实际 MySQL 主机、账户、密码和库名。客户端配置填写本机服务端地址、端口和客户端标识。准备完成后，依次运行服务端、Client B、Client A 的启动脚本，并分别完成密钥协商。

历史源码目录内的配置保持原样，仅为兼容和历史记录；新的脚本入口不读取这些历史实际配置。

## 不应提交或展示的内容

- `runtime/` 下的所有本机 JSON 配置和共享内存相关运行数据；
- `*.pem`、运行时生成的客户端公钥、RSA 私钥和会话密钥；
- 真实数据库账户、密码、连接地址及任何备份；
- 含完整 SQL、明文、密文或密钥材料的日志。

`.gitignore` 用于避免误跟踪新文件，但不会删除已存在的本机文件，也不会抹除历史提交中的敏感信息。

## 泄露处置原则

若凭据或私钥已推送到远程仓库，应立即停止继续暴露、在有管理权限的环境中轮换受影响凭据和密钥，并单独评估远程历史清理与通知范围。不要通过覆盖本机配置来猜测或恢复数据库权限。

密码和密钥轮换属于本机或数据库管理操作，项目初始化脚本不会代为执行。
