# 构建说明

[返回项目首页](../README.md)

## 支持环境与依赖

主入口为 CMake 3.16 及以上，语言标准为 C++17。项目使用 epoll、pthread 和 System V 共享内存，支持目标为 Linux；Windows 用户在 WSL2 或 Visual Studio 的远程 Linux 环境中构建，不是 MSVC 原生 Windows 程序。

| 依赖 | 用途 |
| --- | --- |
| C++17 编译器、CMake、pkg-config | 构建与依赖发现 |
| OpenSSL 开发库 | RSA、AES-GCM 及已有密码封装 |
| protoc 与 Protobuf C++ 开发库 | 从协议源生成匹配本机版本的代码 |
| JsonCpp 开发库 | JSON 配置 |
| MySQL 客户端开发库 | 服务端持久化访问 |
| MySQL 服务端、MySQL 命令行客户端 | 运行与初始化数据库；编译本身不连接数据库 |

Ubuntu 22.04 / 24.04 的依赖准备示例：

```bash
sudo apt update
sudo apt install build-essential cmake pkg-config libssl-dev \
  protobuf-compiler libprotobuf-dev libjsoncpp-dev \
  default-libmysqlclient-dev mysql-client
```

需要本机数据库时另行安装和启动 `mysql-server`；使用既有数据库则无需再装一套。数据库用户必须能按实际配置登录，项目不会修改账户或密码。

## 下载与构建

下载项目并进入仓库根目录：

```bash
git clone https://github.com/ImMike11451/Encrypted_transmission_Demo.git
cd Encrypted_transmission_Demo
```

执行构建：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```

默认产物：

```text
build/bin/encrypted-client
build/bin/encrypted-server
build/generated/MessageV2.pb.h
build/generated/MessageV2.pb.cc
```

构建时不创建数据库、不读取真实配置、不启动网络服务。运行准备与启动步骤见[演示指南](demo-guide.md)。

## 构建选项

| 选项 | 默认值 | 作用 |
| --- | --- | --- |
| `BUILD_CLIENT` | `ON` | 构建客户端 |
| `BUILD_SERVER` | `ON` | 构建服务端；启用时需要 MySQL 开发库 |
| `BUILD_TESTING` | `OFF` | 构建两个已有离线测试目标 |
| `CMAKE_BUILD_TYPE` | 由使用者指定 | 单配置生成器可选 `Debug` 或 `Release` |

只构建客户端：

```bash
cmake -S . -B build-client -DCMAKE_BUILD_TYPE=Release -DBUILD_SERVER=OFF
cmake --build build-client --parallel
```

只构建离线测试，不需要 MySQL 或 JsonCpp：

```bash
cmake -S . -B build-tests -DBUILD_CLIENT=OFF -DBUILD_SERVER=OFF -DBUILD_TESTING=ON
cmake --build build-tests --parallel
(cd build-tests && ctest --output-on-failure)
```

两个测试目标分别为 `encrypted-core-tests`、`encrypted-message-permission-tests`，不访问实际数据库、网络或真实配置。测试结果以执行后的 CTest 输出为准。

## Protobuf 版本与生成方式

CMake 使用 `ClientSecKey/ClientSecKey/MessageV2.proto` 生成统一协议库。配置时核对它与服务端同名协议是否一致；协议字段发生变更时，两份源文件需要同步。

CMake 在 `build/generated/` 生成并编译 `MessageV2.pb.*`，通过 `DEMO_CMAKE_PROTO` 选择相应头文件。源码目录中的生成文件供 Visual Studio 工程使用。

使用同一安装来源的 `protoc`、头文件和库。可先检查：

```bash
protoc --version
pkg-config --modversion protobuf
```

第二条仅适用于安装了相应 pkg-config 元数据的环境。自定义安装示例（替换成你自己的安装前缀）：

```bash
cmake -S . -B build-custom -DCMAKE_BUILD_TYPE=Release \
  -DProtobuf_INCLUDE_DIR=/opt/protobuf/include \
  -DProtobuf_LIBRARY=/opt/protobuf/lib/libprotobuf.so \
  -DProtobuf_PROTOC_EXECUTABLE=/opt/protobuf/bin/protoc
cmake --build build-custom --parallel
```

这些变量属于 [CMake FindProtobuf](https://cmake.org/cmake/help/latest/module/FindProtobuf.html) 的查找接口。更换依赖安装后优先使用新的构建目录，避免旧缓存影响结果。

## MySQL 开发库查找

服务端会查找 `mysql/mysql.h` 和 `mysqlclient`（或 `mariadb`）库。安装路径特殊时：

```bash
cmake -S . -B build \
  -DMYSQL_INCLUDE_DIR=/opt/mysql/include \
  -DMYSQL_LIBRARY=/opt/mysql/lib/libmysqlclient.so
```

`MYSQL_INCLUDE_DIR` 应为包含 `mysql/mysql.h` 的根目录。

## WSL2 和 Visual Studio

- PowerShell 可通过 `wsl.exe -d Ubuntu --exec cmake ...` 调用同样的构建入口；依赖必须安装在该 Linux 环境里。
- 包含特殊字符或点号的自定义 `-D` 参数在 PowerShell 中建议将整个参数加引号。
- WSL 挂载 Windows 磁盘时如出现时间偏差警告，可在 Linux 文件系统中使用独立构建目录。
- Visual Studio 可连接远程 Linux 环境进行开发；首次部署使用本文的 CMake 命令和 `runtime/` 配置目录。

## 常见构建错误

| 现象 | 检查方向 |
| --- | --- |
| 原生 Windows 配置被拒绝 | 改用 Linux/WSL2；不是缺少某个 Windows SDK |
| 找不到 Protobuf | 安装编译器及开发包，或完整指定自定义安装路径 |
| protoc 与头文件版本不兼容 | 同源安装，换独立构建目录，不手改 `.pb.h` 中的版本检查 |
| 找不到 JsonCpp | 安装 `libjsoncpp-dev`，检查 `pkg-config --modversion jsoncpp` |
| 找不到 MySQL | 安装客户端开发包或指定上述两个变量 |
| OpenSSL 弃用警告 | 检查构建退出状态；弃用警告本身不表示编译失败 |
| 启动时找不到可执行文件 | 确认 `build/bin`，或用 `BUILD_DIR=自定义目录 bash scripts/start-server.sh` |

启动脚本按 Makefiles / Ninja 单配置构建的 `build/bin` 路径查找程序。
